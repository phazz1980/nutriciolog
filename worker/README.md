Расходы обоих шлюзов записываются в один SQLite-backed Durable Object UID; записи дневника не затрагиваются. При недоступном учёте модель не вызывается.

`wrangler.toml` использует `src/cloudflare.js`, binding `QUOTA_OBJECTS` и SQLite migration `quota-sqlite-v1`. Адаптер Яндекса при наличии `SHARED_QUOTA_ENDPOINT` использует общий удалённый счётчик; неверный секрет не включает запасной YDB-счётчик. Без этой переменной остаётся старый режим YDB для безопасного поэтапного развёртывания.

## Настройка и порядок включения

1. Авторизовать Wrangler с правами account/user read и Workers write. Платный тариф не требуется и не включается автоматически.
2. Создать случайный серверный `SHARED_QUOTA_SECRET` (минимум 32 символа), сохранить как Worker secret и отдельную версию Yandex Lockbox. Не выводить в терминал/логи, не помещать в клиент или Git.
3. Публиковать Worker из корня репозитория командой `npx wrangler deploy --config worker/wrangler.toml`. До согласованного включения оставить `SHARED_QUOTA_READY="false"`: публичный шлюз и межсерверный счётчик не принимают платные AI-запросы.
4. В Яндекс настроить `SHARED_QUOTA_ENDPOINT=https://my-nutritionist-advice.340052.workers.dev/internal/quota`, секрет из Lockbox и `AI_MONTHLY_REQUEST_LIMIT=1000`. Собрать ZIP через `yandex/build.py`; остановить вызовы старой версии и дождаться окончания запросов перед переключением.
5. Пользователь разрешил начать новый общий счётчик с нуля. Старые счётчики и расходы YDB не удалять; новая история включает только вызовы после переключения и не является полным историческим итогом за месяц.
6. После подключения обеих сторон включить `SHARED_QUOTA_READY="true"` в Cloudflare. Проверить оба шлюза, авторизованный usage и общее списание. Старые публичные версии/адреса с независимой квотой не должны принимать запросы.
7. Только после серверной проверки публиковать клиентский резерв. Автопереключение реализовано локально в сайте, телефонном APK 0.3.5 и Wear 0.2.11, но клиенты ещё не выпущены. UI не показывает названия серверов. Не более одного повтора при сетевой ошибке/тайм-ауте/5xx, отсутствие повтора при 4xx, корректные заголовки токена для каждого сервера. Повтор может списать ещё одну попытку и дополнительные расходы; этот риск согласован пользователем.

`/internal/quota` доступен только по серверному секрету, без публичного CORS. UID берётся из проверенного Firebase-токена шлюзом, а не клиентским запросом. Секрет не открывает дневник, Firebase или API провайдера. Допустимы только read/consume/startCost/finishCost/readCosts; изменение лимита удалённым вызовом запрещено. Операции списания и завершения расходов транзакционные; незавершённые расходы отмечаются неполными.

Проверки: `node --test tests/shared-quota.test.mjs tests/quota.test.mjs tests/costs.test.mjs tests/yandex.test.mjs` — 19/19; сборка `npx wrangler deploy --config worker/wrangler.toml --dry-run --outdir .test-tools/cloudflare-build` проходит. Unit-тесты используют сериализованное тестовое хранилище. Дополнительно прошёл tests/shared-quota-runtime.test.mjs в настоящем локальном Wrangler/SQLite (QUOTA_RUNTIME_TEST=1, порт 8788, локальный тестовый секрет из теста, limit=3/SHARED_QUOTA_READY=true через --var). Это не рабочий Cloudflare: live модель и списание не проверены, фактические CPU/бесплатные лимиты ещё не измерены.

Запросы совета и сохранение блюда по-прежнему раздельны: только явное пользовательское подтверждение записывает дневник. Объявление о недоступности ИИ на главной остаётся отдельной незавершённой задачей.
