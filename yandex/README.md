# AI-шлюз x20 в Yandex Cloud Functions

Клиент настроен на https://functions.yandexcloud.net/d4evergfv4q48plpsdbu. Авторизация,
провайдеры и контракт `{ advice, proposedMeal, proposedProducts }` общие с Worker.
Фото не сохраняются. Месячная квота — 1000 запросов на Firebase UID. В исходниках шлюза 0.1.20 добавлена оценка расходов по usage Blackroute; оплата не подключается.

## Подготовка

Из корня репозитория: `python yandex/build.py`.
Архив `yandex/function.zip` содержит только обработчик и серверные модули.

## Развёртывание функции

1. Создать функцию `x20-ai-test` в выбранном каталоге Yandex Cloud.
2. Создать версию: Node.js 22 (или более новый поддерживаемый runtime), 256 МБ,
   таймаут 60 секунд, точка входа `index.handler`; загрузить `function.zip`.
3. Указать переменные окружения:
   - `AI_PROVIDER=blackroute`
   - `BLACKROUTE_MODEL=deepseek-v3.2-maas`
   - `BLACKROUTE_VISION_MODEL=gemini-2.5-flash`
4. Секрет `BLACKROUTE_API_KEY` подключить из Yandex Lockbox в одноимённую
   переменную. Выдать сервисному аккаунту функции доступ только к нужному секрету
   (роль `lockbox.payloadViewer`). Ключ не помещать в ZIP, Git или клиент.
5. Разрешить публичный вызов функции. Это открывает вход HTTPS, но AI всё равно
   требует проверенный Firebase ID token. Не использовать `integration=raw`.
6. GET `https://functions.yandexcloud.net/<ID>` должен показать health JSON.
   Это проверяет запуск и наличие ключа, но не доказывает доступ к Blackroute.

## Авторизация и переключение

Yandex при прямом HTTP-вызове удаляет `Authorization`, поэтому Firebase-токен
передаётся в `X-X20-Authorization: Bearer <Firebase ID token>`. Обработчик
восстанавливает его для общей проверки подписи. Токен нигде не логируется.
Клиент автоматически выбирает этот заголовок для `functions.yandexcloud.net`.
Для будущего собственного домена/API Gateway потребуется явная конфигурация
заголовка; текущая автоматическая настройка относится только к прямому URL.

Для теста отдельной копии сайта заменить `AI_ENDPOINT` в `js/ai-client.js`
на URL тестовой функции. Origins ограничены двумя текущими доменами и
`https://localhost` для Android-контейнера Capacitor. Новый тестовый домен нужно
явно добавить в ALLOWED_ORIGINS и Firebase Authorized domains; для Capacitor
добавьте в Firebase домен `localhost` (без схемы).
Не менять рабочий сайт до проверки текста, фото, 401, CORS и доступа без VPN.
Откат: вернуть прежний AI_ENDPOINT. Публикация сайта требует повышения версии
интерфейса и кэша согласно AGENTS.md.

Фото перед отправкой преобразуются в JPEG до 1600 px и 1 400 000 символов
Base64 data URL. Исходный лимит выбора 4 МБ сохранён. Обработчик ограничивает
JSON body 1 800 000 байт. Сжатие может ухудшить чтение мелких этикеток;
проверить на физических Android/iPhone. Фото остаётся только в памяти запроса.

Общий таймаут вызовов модели, включая повтор, 40 секунд; клиент — 60 секунд. Оставшееся время нужно для проверки токена, квоты и записи оценки расходов.
При превышении сервер возвращает 504. Проверка Google JWK выполняется отдельно.

## Ручная публикация

Архив функции собирается из корня командой `python yandex/build.py`. В Cloud Functions выберите функцию `nutrition`, источник «ZIP-архив», прикрепите `yandex/function.zip` и сохраните новую версию. Не меняйте точку входа `index.handler`, сервисный аккаунт `x20-ai`, Lockbox и переменные YDB/Blackroute.

Клиент публикуется после проверки функции: из корня выполните `git add -A`, `git commit`, `git fetch origin main`, `git rebase origin/main`, `git push origin HEAD:main`. Workflow `Deploy to Yandex Object Storage` загрузит сайт. Проверяйте версию в `js/core.js`, а после deploy откройте сайт в новой вкладке или обновите Service Worker.
Проверяются endpoint опубликованного клиента, health, CORS и отказ без токена
или с невалидным токеном. Ключи и аккаунт не нужны; платных вызовов модели нет.

При приёмке v0.2.44 проверены реальный вход Firebase, текстовый ИИ, фото и
сохранение дневника после перезагрузки. Доступ на физических Android/iPhone,
в других сетях без VPN, счёт и метрики требуют отдельной проверки.

## Месячная квота запросов

1. Используйте serverless-базу YDB с Document API. Создайте **документную** таблицу `ai_monthly_usage` через Document API `CreateTable` с телом из `yandex/quota-table.json`. Обычная SQL-таблица не заменяет документную. Ключ: `uid` (String, HASH), `period` (String, RANGE); `used` создаётся при первом списании.
2. Сервисному аккаунту функции нужен доступ чтения/изменения этой таблицы (роль `ydb.editor` на предназначенной для квот базе). Не выдавайте доступ браузеру и не добавляйте Firebase service account. У функции уже должен оставаться доступ к секрету Blackroute в Lockbox.
3. У версии функции задайте `YDB_DOCAPI_ENDPOINT` (полный Document API endpoint из обзора базы), `YDB_QUOTA_TABLE=ai_monthly_usage` и `AI_MONTHLY_REQUEST_LIMIT=1000`. IAM-токен берётся из `context.token.access_token` при каждом вызове; постоянный ключ YDB не требуется.
4. Выполните `python yandex/build.py`, загрузите `function.zip`, сохранив текущие переменные моделей, привязку Lockbox, сервисный аккаунт и таймаут 60 секунд. ZIP автоматически включает модули квот из `worker/src`.
5. Проверьте health: версия `0.1.19`, `quotaConfigured: true`. Это подтверждает конфигурацию, но не доступ к таблице. После входа в приложение запрос остатка должен вернуть 1000, реальный запрос — 999. На отдельной тестовой функции с лимитом 1 проверьте, что второй запрос даёт 429 и не вызывает модель; в рабочей функции оставьте 1000.
6. Только после этого публикуйте клиент. Отключите прежние публичные шлюзы без квот, использующие тот же ключ провайдера: старый endpoint иначе позволяет обойти лимит приложения.

Проверка и списание выполняются одним условным `UpdateItem`, поэтому параллельные экземпляры функции не превышают лимит. Получение остатка использует согласованное чтение. Месяц определяется сервером в UTC; 1-го числа используется новый ключ периода, cron для сброса не нужен. Перезапуск функции не сбрасывает квоту. При ошибке YDB ИИ закрыт с 503, локального резервного счётчика нет.

Для квоты хранятся UID, месяц и число принятых запросов, без вопросов, фото и данных дневника. С версии 0.1.20 в этой же таблице хранятся записи оценки расходов (см. ниже). История не удаляется автоматически; её очистка и удаление по запросу пользователя выполняются администратором. Лимит не защищает общий бюджет от создания множества аккаунтов; глобальный бюджет и платежи остаются отдельной задачей.

## Включение оценки расходов (0.1.20)

Пересоберите ZIP и опубликуйте новую версию функции с прежними переменными, Lockbox и сервисным аккаунтом. Новая таблица не нужна: используются ключи `(uid, cost:YYYY-MM-DD:UUID)` в `ai_monthly_usage`. Нужны операции PutItem, UpdateItem и Query; существующая роль ydb.editor должна их разрешать. До публикации новой функции клиент показывает недоступность учёта.

Перед моделью условный PutItem сохраняет неизвестную стоимость; после ответа условный UpdateItem заменяет её суммой всех попыток. Повторное завершение не удваивает расходы. При сбое финальной записи остаётся неизвестная сумма. Если исходная запись не удалась, модель не вызывается (503), уже списанная попытка квоты сохраняется. Query читает только UID из проверенного токена с пагинацией за нужные даты, без Scan.

Тарифы пользователя от 2026-10-06: DeepSeek v3.2 — $0.27/$1.10, Gemini 2.5 Flash — $1.25/$10 за миллион входных/выходных токенов. Это оценка по округлённым примерам, не фактический счёт провайдера. Неизвестные модели, отсутствующий usage и сетевые ошибки помечаются как неполные данные. История до включения учёта не восстанавливается. Периоды UTC, неделя с понедельника. Суммы сохраняются целыми нанодолларами, поэтому смена тарифов не пересчитывает прошлые записи.

Проверка: `node --test tests/costs.test.mjs tests/quota.test.mjs`; после публикации проверить авторизованный `POST {"action":"usage"}` и реальный usage Blackroute. Клиент получает `{quota, costs}`; запросы модели сохраняют прежний контракт. Не следует считать мок-проверки подтверждением работы YDB или наличия usage в реальном ответе провайдера.

Документация: [HTTP Document API и создание таблицы](https://yandex.cloud/en/docs/ydb/docapi/tools/aws-http), [условный UpdateItem](https://yandex.cloud/en/docs/ydb/docapi/api-ref/actions/updateItem), [IAM-токен в контексте функции](https://yandex.cloud/en/docs/functions/lang/nodejs/context).
