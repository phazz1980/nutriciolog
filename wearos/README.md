Чтение JSON/очереди/черновика, а также первая инициализация Firebase выполняются на IO, не блокируя композицию/нажатия на общем замке дисковой записи. На главном экране обычный LazyColumn вместо масштабируемого списка. Вода/вес: кнопки «✓» (сохранить) и «×» (назад без сохранения) в одном ряду, одинаковый фон/шрифт/размер 48 dp, без цветных emoji, с accessibility-подписями; сохранить можно только изменённое допустимое значение.

Wear 0.2.5/versionCode 7 исправляет продолжение уточнений ИИ: под вопросом появляется «Ваш ответ» и «Ответить голосом», затем «Уточнить и рассчитать». Экран прокручивается к ответу автоматически. Повторный запрос включает исходный продукт и последние вопросы/ответы (в пределах лимита шлюза 1000 символов); ошибка сети не теряет ответ. Вопрос, ответ и контекст хранятся вместе с UID-разделённым черновиком и очищаются после добавления еды/изменения исходного описания. После полноценного расчёта появляется отдельное «Добавить в дневник», автоматического сохранения нет. 12 JVM-тестов прошли; реальный разговор/диктовку проверяет пользователь.

Главный экран сразу показывает последнюю сохранённую сводку текущего UID/дня, не ожидая Firebase. Вода, вес, записи еды и текстовый черновик сохраняются в приватном хранилище приложения; запись на диск выполняется вне UI-потока. Гость и аккаунты разделены, гостевые изменения не переносятся автоматически в аккаунт. Старый неразделённый резерв воды не присваивается пользователю: после обновления вода аккаунта восстанавливается из Firebase при первой успешной загрузке. Токены/пароли не копируются в этот кэш, аудио не сохраняется приложением.

Подтверждённые изменения сначала фиксируются локально. Очередь сохраняется после перезапуска и отправляется только под соответствующим UID, со стабильными ID и защитой от запоздалого подтверждения старой версии воды/веса. Firestore SDK также использует постоянный офлайн-кэш и продолжает уже отправленные операции после возврата сети. Приложение повторяет собственную очередь при запуске/возврате на экран и нажатии карточки калорий. При серверном отказе запись остаётся локальной; отображается предупреждение, повтор требует открытия приложения/нажатия карточки. Полноценного разрешения конфликтов разных устройств нет: вода/вес используют последнее сохранение. Работа собственного обработчика очереди при закрытом приложении не заявляется.

«Добавить еду → Продиктовать» открывает системное распознавание русской речи Wear OS. Пример: «яблоко 150 граммов» или одно целое блюдо с порцией. Распознанный текст можно исправить клавиатурой. «Рассчитать с ИИ» использует существующий защищённый AI-шлюз/Firebase ID token и месячную квоту; серверные ключи в часы не передаются. Результат показывает массу, калории, БЖУ и переключатель приёма пищи. Запись за сегодня создаётся **только** после «Добавить в дневник»; диктовка/ответ ИИ/назад ничего не добавляют. Если оценка неверна — исправьте текст и рассчитайте повторно. Несколько отдельных продуктов в одном ответе не сохраняются молча: приложение просит вводить по одному.

Без интернета доступен сохранённый дневник, вода, вес и текстовый черновик; полученный раньше и явно подтверждённый расчёт можно поставить в очередь. Расчёт ИИ требует сети и входа. Доступность диктовки/офлайн-распознавания зависит от системного провайдера на конкретных часах; при отсутствии activity показана подсказка использовать клавиатуру. Запись еды в гостевом режиме через ИИ не предоставляется, черновик доступен.

Проверки: `:app:testDebugUnitTest` — 9 JVM-тестов локального хранилища/очереди/валидации ответа; `:app:assembleDebug` — APK. Реальная диктовка, AI-расчёт, подтверждение и доставка офлайн-записи на физическом устройстве требуют отдельной приёмки.

## Первый запуск

Wear OS 0.2.3/versionCode 5 отображает код входа как 1234-5678 (8 цифр); на телефоне нужен APK 0.3.1 либо PWA v0.2.54, где тире добавляется автоматически. Уже подключённую сессию Firebase обновление не сбрасывает.

В версии 0.2.2 исправлена повторная инициализация Firebase при пересоздании Activity. firebase.properties требуется только на компьютере при сборке, его значения встраиваются в APK; отдельный файл на часах не нужен. Ошибка отсутствия настроек теперь отделена от сбоя инициализации SDK.

1. В Firebase Console зарегистрируйте Android-приложение с пакетом `ru.mynutritionist.wear` в уже используемом проекте `my-nutritionist-67ce8`. Включите Email/Password, если он ещё не включён.
2. Скопируйте `firebase.properties.example` в `firebase.properties` и укажите Firebase Android app ID, API key и project ID. Файл игнорируется Git; эти идентификаторы клиентские, но не должны случайно смешиваться с конфигурацией другого Android-приложения.
3. Откройте каталог `wearos` в Android Studio (JDK 17, Android SDK Platform 37.2 и Build Tools 37), синхронизируйте Gradle и запустите модуль `app` на эмуляторе Wear OS или часах. Для сборки из консоли используйте Gradle 9.3.1 или новее.

Для синхронизации пользователь входит по email/password с тем же аккаунтом, что и в PWA. Для этого способа отдельный сервер не требуется. При отсутствии конфигурации или аккаунта вода сохраняется локально на часах.

## Главный экран и вход с телефона

Главный экран сохраняет кнопки: «Вода: N / 8» открывает отдельный экран с заголовком «Вода», кнопками − / + по бокам количества, сохранением и отменой. До сохранения облачных изменений нет. «Вес: N кг» показывает последнюю запись не позднее сегодняшнего дня и открывает ввод веса. Начиная с 0.2.4 вода/вес сохраняются локально сразу, без ожидания серверного подтверждения. Три чтения Firebase выполняются параллельно в фоне с таймаутом 4 секунды; ошибка сети не обнуляет сохранённую сводку. Это убирает сетевое ожидание, но не является доказательством устранения всех аппаратных лагов.

Вход без набора пароля на часах подготовлен через одноразовый код, без нативного приложения-компаньона. На часах: «Аккаунт → Войти с телефона». В авторизованном PWA на телефоне: «Профиль → Подключить часы», ввод кода, проверка и отдельное подтверждение. Часы получают собственную Firebase-сессию того же UID; пароль и refresh token телефона не передаются. Устройства должны иметь доступ к интернету; прямой Bluetooth-протокол не используется.

Сервис Yandex wear-auth опубликован: `https://functions.yandexcloud.net/d4e5bfebi143u6kitt0v`. Этот публичный адрес включён в PWA и APK 0.2.1; `WEAR_AUTH_ENDPOINT` в локальном `firebase.properties` позволяет его переопределить. Установите новый APK на часы и обновите PWA на телефоне. Создание/опрос/отмена кода проверены на сервере; реальное подтверждение с телефона и Firebase-вход на физических часах ещё требуют проверки. Сервис не связан с ИИ-шлюзом. При потере ответа с одноразовым токеном получите новый код.

Для debug-сборки используется Gradle 9.6.0; остаётся предупреждение AGP 9.1.1 о compile SDK 37.2, не препятствующее сборке. Плавность на физических часах требует повторной проверки пользователем; эмулятор не заменяет такую проверку.

Перед публикацией в Play Console потребуются собственная подпись, скриншоты, политика конфиденциальности и зарегистрированный Android package; APK/AAB и `firebase.properties` не добавляйте в Git.
