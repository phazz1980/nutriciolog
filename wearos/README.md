# «Мой нутрициолог» для Wear OS

Нативный минимальный клиент Wear OS 4+ (API 30): показывает сегодняшние калории из общего дневника, быстро отмечает стаканы воды и записывает вес. Он использует те же пути Firestore, что и PWA: `users/{uid}/foodDiary`, `waterLogs` и `weightEntries`.

ИИ, камера, редактирование еды и хранение фото намеренно не перенесены на маленький экран. Запись еды остаётся в PWA, где пользователь может проверить значения и явно подтвердить сохранение.

## Первый запуск

Wear OS 0.2.3/versionCode 5 отображает код входа как 1234-5678 (8 цифр); на телефоне нужен APK 0.3.1 либо PWA v0.2.54, где тире добавляется автоматически. Уже подключённую сессию Firebase обновление не сбрасывает.

В версии 0.2.2 исправлена повторная инициализация Firebase при пересоздании Activity. firebase.properties требуется только на компьютере при сборке, его значения встраиваются в APK; отдельный файл на часах не нужен. Ошибка отсутствия настроек теперь отделена от сбоя инициализации SDK.

1. В Firebase Console зарегистрируйте Android-приложение с пакетом `ru.mynutritionist.wear` в уже используемом проекте `my-nutritionist-67ce8`. Включите Email/Password, если он ещё не включён.
2. Скопируйте `firebase.properties.example` в `firebase.properties` и укажите Firebase Android app ID, API key и project ID. Файл игнорируется Git; эти идентификаторы клиентские, но не должны случайно смешиваться с конфигурацией другого Android-приложения.
3. Откройте каталог `wearos` в Android Studio (JDK 17, Android SDK Platform 37.2 и Build Tools 37), синхронизируйте Gradle и запустите модуль `app` на эмуляторе Wear OS или часах. Для сборки из консоли используйте Gradle 9.3.1 или новее.

Для синхронизации пользователь входит по email/password с тем же аккаунтом, что и в PWA. Для этого способа отдельный сервер не требуется. При отсутствии конфигурации или аккаунта вода сохраняется локально на часах.

## Главный экран и вход с телефона

Главный экран сохраняет кнопки: «Вода: N / 8» открывает отдельный экран с заголовком «Вода», кнопками − / + по бокам количества, сохранением и отменой. До сохранения облачных изменений нет. «Вес: N кг» показывает последнюю запись не позднее сегодняшнего дня и открывает ввод веса. Локальное сохранение воды и веса не ждёт сеть бесконечно: подтверждение Firestore ожидается до 5 секунд, затем интерфейс сообщает об ожидании сети; SDK продолжает отправку при восстановлении связи. Локальный резерв веса разделён по UID.

Вход без набора пароля на часах подготовлен через одноразовый код, без нативного приложения-компаньона. На часах: «Аккаунт → Войти с телефона». В авторизованном PWA на телефоне: «Профиль → Подключить часы», ввод кода, проверка и отдельное подтверждение. Часы получают собственную Firebase-сессию того же UID; пароль и refresh token телефона не передаются. Устройства должны иметь доступ к интернету; прямой Bluetooth-протокол не используется.

Сервис Yandex wear-auth опубликован: `https://functions.yandexcloud.net/d4e5bfebi143u6kitt0v`. Этот публичный адрес включён в PWA и APK 0.2.1; `WEAR_AUTH_ENDPOINT` в локальном `firebase.properties` позволяет его переопределить. Установите новый APK на часы и обновите PWA на телефоне. Создание/опрос/отмена кода проверены на сервере; реальное подтверждение с телефона и Firebase-вход на физических часах ещё требуют проверки. Сервис не связан с ИИ-шлюзом. При потере ответа с одноразовым токеном получите новый код.

Для debug-сборки используется Gradle 9.6.0; остаётся предупреждение AGP 9.1.1 о compile SDK 37.2, не препятствующее сборке. Плавность на физических часах требует повторной проверки пользователем; эмулятор не заменяет такую проверку.

Перед публикацией в Play Console потребуются собственная подпись, скриншоты, политика конфиденциальности и зарегистрированный Android package; APK/AAB и `firebase.properties` не добавляйте в Git.
