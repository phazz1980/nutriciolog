## Проект

«Мой нутрициолог» — статическое PWA с дневником питания, планом питания, водой/весом, ИИ-советами, фото блюда и браузерным голосовым вводом.

Целевая схема:

`Cloudflare Pages (клиент) → Cloudflare Worker (ИИ-шлюз) → ИИ-провайдер`

Пользовательские данные синхронизируются через Firebase клиентом, а не Worker.

## Что присутствует в текущем архиве

- `index.html` — основной интерфейс приложения.
- `photo-picker.js` — выбор источника для распознавания блюда: камера или галерея/файлы.
- `firebase-client.js` — Firebase Web config, Auth/Firestore и локальная работа.
- `firestore.rules` — доступ к `users/{uid}/...` только текущему авторизованному UID.
- `manifest.webmanifest`, `service-worker.js`, `pwa.js`, `icons/app-icon.svg` — PWA.
- `worker/wrangler.toml` — Worker `my-nutritionist-advice`, `AI_PROVIDER = "blackroute"`, экономичная модель `gemini-2.5-flash-lite` для распознавания фото.
- `worker/src/index.js` — HTTP-обработчик `/api/advice`/Worker: POST/OPTIONS, CORS, валидация текста и фото, вызов выбранного ИИ-провайдера.
- `worker/src/providers/` — адаптеры Blackroute/OpenAI и выбор провайдера; системная инструкция ограничивает ответы общими вопросами питания и ЗОЖ.
- `README.md` — инструкции по GitHub Pages, Cloudflare Worker, Firebase, фото, голосу и PWA.
- В профиле есть форма редактирования имени, возраста, роста, текущего/целевого веса, цели и дневной нормы; значения сохраняются в `profile/main` через Firebase или в local fallback. При Google-входе в карточке и в правой части главной страницы отображаются имя и аватар аккаунта, а email остаётся только в статусе синхронизации. Приветствие на главной странице выбирается по местному времени пользователя. Имя подставляется как начальное значение даже при временной ошибке чтения профиля, но сохранённое пользователем имя не перезаписывается. Медицинские параметры у Google не запрашиваются.
- После входа приложение не использует гостевой профиль как fallback: используется UID-кэш и фоновая загрузка `users/{uid}/profile/main`, чтобы данные другого режима не подменяли профиль аккаунта.
- Вода, ручные записи дневника и запись веса сохраняются через `nutritionStore` в соответствующие Firestore-коллекции; без Firebase или входа работает local fallback. Дневник изначально пуст, а новые позиции одного приёма пищи объединяются в одну карточку; записи текущего дня загружаются из хранилища при запуске, а блоки приёмов пищи всегда расположены как «Завтрак → Обед → Ужин → Перекус». Каждую отдельную запись, включая перекус, можно удалить из Firebase или local fallback. В шапке дневника остаётся только ручное добавление блюда; для ИИ используется отдельная вкладка «Совет». БЖУ ручной записи вводятся в форме, БЖУ продукта ИИ приходят из подтверждённой карточки; главная сводка складывает сохранённые значения, а целевые БЖУ выводятся из калорийности профиля по схеме 30/30/40. Раздел «План питания» убран из интерфейса.
- Рядом с названием дня в дневнике есть кнопка календаря 📅. По выбранной прошлой дате, сегодняшнему или завтрашнему дню она читает сохранённые записи из Firebase или local fallback, группирует их по приёмам пищи и показывает порции, БЖУ и сумму калорий прямо в дневнике. Просмотр не изменяет записи выбранной даты.
- В ручной форме блюда есть действие «Рассчитать с ИИ»: по названию и введённому весу порции Worker возвращает ориентировочные калории и БЖУ, которые подставляются в форму без автоматического сохранения. Для расчёта нужен вход через Google, поскольку доступ к Worker требует Firebase ID token.
- Если ИИ запрашивает уточнение для расчёта, ответ пользователя передаётся только в повторный расчёт и не дописывается к названию блюда в форме. После подтверждённого сохранения вопрос ИИ и ответ с дополнительными ингредиентами хранятся в личной базе продукта; при следующем вводе того же названия отображается напоминание.
- Загрузка дневника при инициализации и входе выполняется через единый обработчик даты; номер версии загрузки отбрасывает устаревший параллельный ответ, поэтому записи не задваиваются в интерфейсе.
- В форме ручного добавления поле «Приём пищи» начинается пустым и обязательно для выбора; выбранное значение сохраняется в записи дневника.
- Выбор приёма пищи сохраняется в памяти текущей страницы и подставляется при следующем открытии формы до перезагрузки сайта.
- При загрузке текущего дня записи передаются в финальный отрисовщик, который упорядочивает карточки как «Завтрак → Обед → Ужин → Перекус».
- Вода восстанавливается только для текущей даты из Firebase или local fallback; новая дата автоматически начинает счётчик с нуля.
- Вместо временного имени профиля показывается статус загрузки; данные отображаются сразу после получения, а запасной профиль — через 10 секунд.
- При попытке ИИ-расчёта без входа показывается модальное окно «Нужна авторизация». Нажатие «Перейти к входу» по явному действию пользователя открывает Google Authentication; если Firebase ещё недоступен, открывается профиль.
- В ручном добавлении используется одно поле «Порция» без переключателя единиц. Для небольшого целого количества счётных продуктов приложение автоматически выбирает штуки, иначе граммы. После подтверждённого сохранения личная база продукта может хранить `unitWeight` — вес одной штуки; при следующем ИИ-расчёте в штуках он передаётся как приоритетное значение.
- У каждого пользователя есть личная база `users/{uid}/products/{normalizedName}` с калориями и БЖУ на сохранённую порцию; гостевой режим использует local fallback. ИИ может вернуть несколько отдельных карточек продуктов, но каждая запись требует выбора приёма пищи, даты «Сегодня / Завтра» и явного нажатия «Добавить», после чего сохраняется в дневник и личную базу. Такой же выбор даты есть в ручной форме и у предложения блюда ИИ.
- Внизу профиля отображаются номер версии и дата выпуска. Их нужно обновлять при каждой фиксации версии одновременно с Git-тегом.

## Ключевые архитектурные решения

- Cloudflare Pages содержит только публичный клиентский код; GitHub-репозиторий может оставаться приватным.
- ИИ-секреты хранятся только в Cloudflare Worker secrets; активный провайдер — Blackroute с DeepSeek.
- Worker не имеет Firebase service account и не записывает дневник.
- Ответ ИИ имеет единый контракт `{ advice, proposedMeal }`.
- Контракт расширен необязательным для старого клиента полем `proposedProducts`: массивом до 8 предложений `title`, `portion`, `calories`, `protein`, `fat`, `carbs`, `mealType`; запись выполняет только клиент после подтверждения.
- `proposedMeal` является предложением: запись выполняется только после явного подтверждения пользователя.
- Фото JPEG/PNG/WebP до 4 МБ отправляется на один ИИ-запрос и по умолчанию не сохраняется.
- Голосовой режим использует только браузерный Web Speech API для распознавания речи; озвучивание ответов в браузере отключено и отдельный аудио-backend не требуется.
- Service Worker кэширует оболочку приложения; облачные Firebase/ИИ-функции требуют сети.

## Известные ограничения / незавершённая внешняя настройка

- ИИ доступен всем пользователям, вошедшим через Firebase. Это увеличивает потенциальные расходы Blackroute; при необходимости вернуть доступ по списку email отдельной задачей.
- Фото постоянно не хранятся; Firebase Storage не настроен и сейчас не требуется.
