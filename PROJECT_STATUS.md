# PROJECT_STATUS.md — текущее состояние проекта

Последняя проверка: 2026-09-27
Версия интерфейса: `v0.2.20`

## Назначение

«Мой нутрициолог» — статическое PWA для GitHub Pages / Cloudflare Pages:

`Cloudflare Pages → Cloudflare Worker → ИИ-провайдер`

Клиент хранит дневник питания, воду, вес, профиль и личную базу продуктов через Firebase. При недоступном Firebase пользователь может явно продолжить работу в гостевом режиме с локальным `localStorage`.

## Структура

- `index.html` — разметка приложения.
- `styles.css` — стили интерфейса, вынесенные из `index.html`.
- `app.js` — клиентская логика интерфейса, дневника, профиля, воды, веса, ИИ-запросов и модальных окон.
- `firebase-client.js` — Firebase Auth/Firestore, кэш профиля и локальный fallback.
- `photo-picker.js` — выбор камеры или галереи.
- `pwa.js`, `service-worker.js`, `manifest.webmanifest`, `icons/` — PWA и кэш оболочки.
- `firestore.rules` — доступ Firestore только текущему UID.
- `worker/src/index.js` — Worker с POST/OPTIONS, CORS, проверкой Firebase ID token и валидацией входа.
- `worker/src/providers/` — адаптеры Blackroute/OpenAI.
- `tests/auth-network.cjs` — браузерные проверки авторизации и сетевых отказов.

## Реализовано

- Google Authentication и вход по email/password с обработкой медленной сети, повторным подключением и явным гостевым режимом. Для email-аккаунтов доступны письма восстановления и подтверждения адреса: письмо отправляется после регистрации, а в профиле есть повторная отправка и проверка статуса. Вошедший через Google пользователь может привязать пароль к тому же email и затем безопасно перейти на email-вход без потери UID и данных.
- UID-разделение данных в Firestore; кэшируется только профиль, токены не сохраняются вручную.
- Дневник с ручным добавлением, удалением записей, просмотром прошлых дат, водой и прогрессом веса.
- ИИ-расчёт БЖУ, распознавание фото, голосовой ввод и предложения продуктов.
- Предложение ИИ сохраняется только после явного подтверждения пользователя.
- Фото отправляется только в рамках запроса и не сохраняется в Firebase.
- Worker настроен на Blackroute: для текста использует `gemini-3-flash-preview`, а для запросов с фото — `gemini-2.5-flash`; секрет `BLACKROUTE_API_KEY` хранится только в Cloudflare Worker Secrets.
- Ограниченный CORS Worker: `https://nutriciolog.pages.dev` и `https://nutriciolog-x20.website.yandexcloud.net`.
- Публичные документы OAuth: `privacy.html` и `terms.html`.
- Удалён переключатель моделей в интерфейсе вкладки «Совет» (приложение использует модель по умолчанию на стороне Worker).
- В форме ручного добавления убраны кнопки распознавания порции по фото и голосового ввода; поле имеет единую подпись «Порция, г / шт.». После распознавания блюда по фото калории и БЖУ заполняются только после ручного ввода веса порции; числовые примеры в полях порции и калорий убраны. Ошибка пустой или нулевой порции показывается стандартной подсказкой браузера рядом с полем и не сдвигает разметку.
- Логотип `icons/nutritionist-logo.png` добавлен в оболочку; текущая версия кэша Service Worker — `v28`.
- Firebase Auth явно использует постоянную browser persistence; Service Worker best-effort кэширует только публичные модули Firebase App/Auth/Firestore, чтобы повторный запуск не ждал их загрузку из `gstatic`. Токены, credentials, Firebase persistence и пользовательские данные не попадают в Cache Storage.
- Все ответы ИИ логируются в консоль браузера с HTTP-статусом для диагностики советника и сценариев блюда; запросы, токены и фото не логируются.
- При ошибке формата ответа Blackroute Worker возвращает авторизованному клиенту диагностический фрагмент ответа модели (до 4 000 символов); вкладка «Совет» показывает его в раскрываемом блоке с копированием. Фрагмент не сохраняется, а похожие на API-ключ строки маскируются.
- Ручное распознавание блюда по фото выполняет один запрос, использует первое корректное предложение продукта, а при пустом списке продуктов — `proposedMeal`, чтобы корректный ответ ИИ заполнял форму. Устаревший параллельный обработчик, вызывавший одновременно ошибку и окно успешного распознавания, отключён.
- При ошибке формата ИИ в ручном распознавании фото форма показывает раскрываемый диагностический фрагмент ответа и позволяет его скопировать; фрагмент приходит только для авторизованного пользователя и не сохраняется.
- При ответе Blackroute в Markdown или другом неподходящем формате Worker один раз автоматически повторяет запрос с явным требованием вернуть только JSON. Только если повтор тоже не прошёл валидацию, клиент получает диагностические фрагменты обеих попыток.
- Каждый запрос Blackroute, включая автоматический повтор после некорректного JSON, получает лимит 1 000 токенов, чтобы структурированный ответ не обрывался.
